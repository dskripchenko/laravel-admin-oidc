# dskripchenko/laravel-admin-oidc

> 🌐 [English](../../README.md) · **Русский** · [Deutsch](../de/README.md) · [中文](../zh/README.md)

Вход в панели [`dskripchenko/laravel-admin`](https://github.com/dskripchenko/laravel-admin)
через OpenID Connect — Keycloak, Microsoft Entra ID, ADFS, Authentik, Okta или
любой OIDC-провайдер. Стандартный OIDC, без кода под конкретный продукт:
различия провайдеров — это настройки.

- **«Войти через …» на экране входа**, под формой пароля, которая остаётся.
- **Учётки создаются при первом входе**; существующая учётка с тем же email
  связывается, только если провайдер подтвердил email.
- **Роли — от провайдера**: значения claim (`realm_access.roles`, `groups`…)
  по маппингу в роли панели, заменяются при каждом входе. Ни одной роли — нет
  входа.
- **Несколько панелей, свои провайдеры у арендаторов** — через ссылку
  `/{panel}/sso/to/{арендатор}` и три небольших контракта хоста.
- **Проверки по OIDC Core**: Authorization Code + PKCE (S256), `state` и
  `nonce`, ID-токен по JWKS провайдера (только асимметричные алгоритмы, смена
  ключей), issuer, аудитория, срок. Запросы к провайдеру — через политику
  адресов (https, частные сети запрещены, кроме белого списка).
- Необязательное **требование MFA** по claim `amr`.

## Установка

```bash
composer require dskripchenko/laravel-admin-oidc
php artisan migrate
```

Нужен laravel-admin 1.50+. Провайдеры настраиваются в панели: **Система →
SSO-провайдеры**.
